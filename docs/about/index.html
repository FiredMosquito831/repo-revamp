About repo-revamp

An independent project by Danube Labs, built from the working playbook of nine public repository revamps and one private product site.

What this is

repo-revamp is a Claude Code plugin. It packages the process of revamping a repository into a skill, 5 slash commands, 3 agents, 17 reference files, 7 templates and 3 scripts. It is distributed through its own marketplace, danube-labs, from the same public repository.

The plugin is not a site generator you point at a folder. It is a playbook with a state machine: it asks the owner questions, freezes the product, delegates one build, verifies the result and deploys on the owner's go. The generator is one part of it.

Status

Version 1.0.1, MIT licensed, public. The plugin validates with claude plugin validate . --strict, the repository's own validator passes, and the CI workflow is green. The site you are reading is generated by the plugin's own rules: a deterministic builder, hard gates, original diagrams, redacted terminal captures and a claims ledger.

The site launches from its own branch and is not merged into the default branch. The plugin and its site are versioned together, but the site is a presentation artifact and is kept separate on purpose.

How this site was built

The site is the plugin's own playbook applied to the plugin. A read-only recon established the facts. A numbered spec asked the owner the decisions that mattered and recorded the answers as a binding decisions block. One implementer built the site in a worktree on its own branch, with the product paths frozen.

The builder reads the repository at build time: it counts the reference files, templates, commands, agents and scripts, reads the version from the plugin manifest, and generates the reference page from the real front matter and file list. Nothing on this site is a number typed from memory.

The honest limits

  • The private-repository posture is documented, not exercised on this repository, which is public.
  • The plugin has no product UI, so the site shows diagrams and terminal captures rather than application screens.
  • The playbook does not publish time or cost estimates per revamp, because neither is measured.
  • A green build proves the output is consistent, not that every sentence is true; the claims ledger is what carries truth.
  • Search indexing and ranking are outside the plugin's control. It submits the sitemap and records the response.

Who builds it

Danube Labs, an independent studio. The source is at github.com/FiredMosquito831/repo-revamp, and the issue tracker there is the contact channel.
