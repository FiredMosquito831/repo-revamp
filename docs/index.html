What it does

Most repositories are judged in the first minute: by the README, by the demo, by whether a search engine can find them at all. A revamp fixes that surface. It is also the kind of work that quietly breaks things, because the person doing it is editing the same repository the product lives in.

repo-revamp turns the work into a playbook with a state machine. A read-only recon establishes the facts. A numbered spec asks the owner the decisions that matter, one recommendation per question. One delegated agent builds a generated site in docs/ behind a deterministic builder and a set of hard gates. The orchestrator verifies every claim itself, deploys on the owner's go, and records what it learned.

The product is frozen throughout. A presentation-only revamp may change the README, the site, the builder, the requirements file, the site workflow and an append-only .gitignore. A boundary diff proves it: if the diff prints a product path, the pull request is out of scope.

The phase state machine

Every revamp moves through eight phases in order. A phase's exit gate must be green before the next one starts, and the state file records where the work stopped, so a fresh session resumes instead of starting over.

The state file is _revamp/<repo>/STATE.md. It holds the phase, the branch, the head, the gates, the open questions and the next action. The revamp-status command prints it in five lines, which is what a resumed session reads first.

What the plugin ships

The repository is small on purpose. The depth lives in the reference files, which are read one phase at a time rather than all at once. The skill is the contract; the references carry the detail; the commands start each part of the work; the agents do the delegated work; the scripts verify and inventory.

Questions people ask first

Does it change my product code?

No. A presentation-only revamp may change the README, the site, the builder, the requirements file, the site workflow and an append-only .gitignore. The boundary diff must print nothing else, and a product change is a stop-and-report event.

What does it need?

Claude Code with plugin support, git, an authenticated gh for the GitHub steps, and Python 3.12 for the scripts. The screenshot clustering needs Pillow and imagehash in a scratch environment, never in the repository.

What happens when a fact cannot be verified?

It is cut. Every factual statement on a generated page needs a row in the claims ledger with evidence that resolves to a file in the repository. A number that appears in no source is a bug, not a rounding decision.
